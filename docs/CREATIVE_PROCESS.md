# 制作ノウハウ：ドクロ・コウモリのライブ投影

## 範囲
この文書は公開済みの[README](../README.md)と[開発ガイド](DEVELOPMENT.md)から、目的・課題・実装上の工夫を整理したものです。記録のない過去の試行や性能改善率は推測しません。新たな機能追加・実機検証・配布更新ではありません。

## 目的
PCとプロジェクターでドクロ・コウモリを映し、演奏中にキーボードで動き・色・文字を変える。追加ソフトやコマンド操作なしで配布ZIPを開けるようにする。

## 課題
投影映像へ操作画面を出さず、手元の操作から非同期に状態を反映する必要がある。文字入力や別窓操作が演奏入力として誤作動しないことも重要。元の動きや画素計算を保ちながらコードを整理する必要がある。

## 実装上の試行と到達点
- **二窓構成**：操作窓でintentを作り、MessagePort経由で投影側が要求を検査して共通APIへ渡す。クリック直後の古い表示ではなく、返答と反映後の状態を待って確認する。
- **演奏用の値**：キーの目標値を約150msで補間。色相は短い方向へ回す。動きの強さ一軸を複数の実パラメーターへ変換する。
- **誤入力対策**：演奏開始を明示し、入力欄や別窓へ移った際はキー受付を解除する。全画面解除と演奏入力解除を区別する。
- **描画処理の整理**：モデル・姿勢、ラスタ、前処理、流体、合成の順序を保つ。流体側がGPU資源を所有し、合成側が借用する。
- **オフライン配布**：生成物と入力ソースを分け、資産一覧・manifest・hash・ZIP内容を照合する。

## 再利用できる技
1. **一つの入力に一つの意味**：停止、暗転・解放、終了を分ける。Pauseは資源を保持し、Stopは解放、Resumeは再構築、Endは保持データも消す。
2. **時計を区別する**：共有時計、固定ステップ、目標値補間、描画ゲートは同じ仕組みではない。
3. **資源所有を明確にする**：別WebGL contextのtextureを共有しない。借用側を先に解放する。
4. **整理と改変を区別する**：和の順番、Float32丸め、GLSL文字列を見た目だけで変更すると結果が変わることがある。構文比較と実際の画像比較は別々に行う。
5. **元画像と実投影を区別する**：旧TouchDesigner版、ブラウザ画面、配布版の実投影は異なる証拠。説明画像も実写の代わりにしない。

## 結果・検証限界
公開READMEにはWindows・Chromeでの配布ZIP起動・操作・オフライン保存と、配布版の実投影動画が記録されています。全PC・全GPU・全OS・全投影機の保証ではありません。CPU単体スイートや構文比較だけでは、ブラウザ描画・長時間運転を保証できません。
