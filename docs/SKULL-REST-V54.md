# Skull size and inertial return v54

At low movement strength, v53 fitted every skull to a rotation sphere and blended that fit into the rest row. With six actors, this reduced the displayed scale to about 0.493–0.514. It was separate from the intended 6% appearance animation. At 1280×720, the original front-facing rig is about 169 px wide at default user scale, so six actors fit the 213 px row spacing without that extra fit.

Rest placement now changes translation only. Its scale stays 1 at every strength and count. The optional legacy rows layout uses the existing fixed maximum noise reference rather than refitting as strength changes. User size and the original camera perspective remain independent; turning a three-dimensional head still changes its projected outline. The model, jaw hinge, surface shader and 6% / 200 ms appearance code are unchanged.

The fixed 450 ms presentation envelope is removed. A small feedback loop keeps only a two-dimensional position and velocity for each visible actor. Retargeting changes the goal while preserving position and velocity. Acceleration is bounded at 1.6 stage heights/s²; a fixed response of 4/s slows the approach near the target. Elapsed seconds drive integration with substeps of at most 1/120 s. There is no per-move deadline, engine, new dependency or user tuning panel. Arrival time depends on distance and initial velocity. The final snap is below 0.0001 stage height and 0.0004 stage height/s. Pause freezes both position and velocity; Resume continues from them. Existing 150 ms numeric cue interpolation changes the input target and does not impose the arrival time.

The original inspected motionMat block subtracts the locked baseline from Feedback, multiplies by 0.98, adds the baseline back, and feeds Cross; upstream Math/Lag also smooth the source. Those connections are statically confirmed. An independent velocity or constant-acceleration state was not found in that block. The Web position/velocity loop is an explicit small presentation adaptation, not a claim that TouchDesigner used the same controller. Original source modules, coefficients and producer cadence are preserved. The full original TOE was not executed or changed.

Accepted B bats, their force behavior and artwork are unchanged. Existing V duration/focus/input guards are unchanged. No licensing, public visibility or main branch change is part of this revision.

Validation uses the actual production module and offline Chrome renderer: counts 1–6, locked-source geometry across strengths and both layouts, independent user size, live strong/quiet reversals, count combinations, appearance scale, Pause/Resume, different distances/initial velocities, production draw/solver counters, resource release and existing input/security routes. Controlled initial-condition probes are named separately from normal UI operations. Capture is sequential and follows original wall-clock timestamps; it is not a performance benchmark. Physical projector output, other hardware and complete native-noise/image equivalence remain outside this verification.
