## 1. 目的と進め方

- **本人:** 商品化の第一歩として、他の人がダウンロードし、TouchDesignerの環境構築なしでブラウザ表示・プロジェクター投影できるアプリを作る。
- **本人:** 投影方法をYouTube動画のように解説できる構成にする。2026年ハロウィンを目標に最小動作版を優先し、間に合わない部分はクリスマスへ回せる構成にする。
- **本人:** 最初は無料提供。後続の承諾で自作コードのMIT（改変・再配布・商用利用を含む）を採用。GitHubとWebは当面privateを維持する。将来のサービス料金・一般公開時期は未決定。未指定の契約条件を追加しない。
- **本人:** 「守」を先に行う。原VJの見た目・動きを再現し、差分を確認してから効率化・改変へ進む。既存4効果GUIの共通部を参考にする。
- **委任範囲:** まず本人向け試作を納品する。販売、YouTube投稿、一般公開、動画や原モデルの追加アップロードは行わない。

## 2. 本人が指定した2シーン

| シーン | 必須の組合せ | 操作・表示 |
|---|---|---|
| A: ドクロ | 回転するドクロ＋流体エフェクト＋背景の文字 | 頭と下顎を独立して動かし、頭の回転と口の開閉を両立する。大きさ・中心・角度を合わせられる。 |
| B: コウモリ | 円から作った本人のコウモリが飛翔＋中央の文字 | 操作で速度や動きを変えられる。キーボードは入力方法の例。 |

**本人:** この2シーンを、同じブラウザ内・同じ表示面で切り替えながら使う。
シーンAの流体と背景文字、シーンBの中央文字は現在の必須要件。
ドクロを3体に固定する指示はない。文字数上限・キー配列・MIDI必須も決められていない。
v0.1の「2D全身骸骨のみ」の画面はシーンAを満たさない。


**本人の許容した生成方法:** コウモリの絵は一度生成したレンダリング画像を再利用してよい。円/矩形の生成ネットワークを毎フレーム移植実行することは必須ではない。
静止画1枚で羽ばたきまで止める意味とはしない。原作の必要なフレーム群/テクスチャ配列を焼き出し、画像再生や変形で羽ばたきを保つ案とする。
画像の生成・再利用と、飛翔シミュレーション・速度/動きのAPIを分ける。原作由来の絵と動きを比較する要求は保持する。

## 5. 入力/APIとパラメーターの設計案

**本人の方針:** 例えばキーボード等で速度/動きを操作し、入力と制御を分ける。
**提案:** 「入力アダプター→共通制御API→検証済みパラメーター状態→選択中の効果」とする。
画面操作とキーボード等が同じAPIを使い、描画ループ内へ直接キー処理を書き込まない。
最初は同一ブラウザ内JavaScript APIとし、HTTPサーバーAPI・MIDI機器を必須にしない。

API案は `select(scene)`、`set(scene,key,value)`、`setText(scene,text)`、
`pause()`、`resume()`、`reset(scene)`、`stop()`、`status()`。
既存GUIのselect/set/status、範囲検証、世代管理、共通RAF、所有資源scopeを共用候補とする。
既存の4効果ID・数値範囲・WebGL2必須条件はそのままコピーしない。

| 項目 | 原作の事実 | ブラウザ案・未確定点 |
|---|---|---|
| 初期速度 | Initialspeedの保存値1.3。発生源の法線を倍率調整して新しい粒子へ渡す。 | `flight.initialSpeed`候補。全個体の速度を即時一律変更する意味とは違う。上限/初期値は基準映像と負荷で決める。 |
| 飛翔の動き | s1がCrossを介しVortex 5↔1、Spiral -1.7↔-0.9を混合する。 | `flight.motionMix`候補、0〜1はAPI案。直接の力調整と混合値が競合する場合の優先規則を定義する。 |
| 発生/寿命/乱れ | batの保存値Birth5/Life5/Turb各.2。別定数には20/2/1.1、子ノードにも異なる保存評価値がある。 | `birth`、`life`、`turbulence`候補。保存式・評価値・定義初期値・商品既定値を区別する。 |
| 羽ばたき | frequeny=1と×4の三角波系、波形Lookup、テクスチャ配列。 | `flapFrequency`は露出候補。元の操作信号への接続は未確認。 |
| 全体の時間倍率 | 同名のspeedスライダーが原VJにあることは未確認。 | `timeScale`はAI案で、初期値1の案。羽ばたき/寿命/流体も速くするかは未決定。Initialspeedと混同しない。 |
| ドクロ/流体 | Jawexp/Jawperiod、Motioncross/Hue、Cross2/Coldiffusion/Noiseamp/Noiseperiodを確認。 | パラメーター名・意味・値域・初期値・保持/Resetの詳細は付録J。必須UIを全項目へ増やす指示ではない。 |

**保持/Reset案:** 文字と各シーンのユーザー設定は切替・Stop後も保持し、非選択効果は更新しない。
切替時と明示Resetでは粒子・残像・流体バッファ・顎/回転の進行を基準初期状態へ戻す。
設定を既定値へ戻す操作は別にする。原VJの絶対時刻/乱数との比較方法を決めてから契約を確定する。
範囲外/NaN/未知keyを更新前に拒否し、採用値をstatusで確認できる設計とする。

## 6. 配布・投影・権利・性能

- **提案（初回操作UI）:** 黒い投影背景、全画面、操作パネルの非表示/復帰、文字編集、最小限の調整を用意する。停止/再開/Resetは本人の既存要求。強い点滅は初期版で不要という委任方針。
- **委任検証項目:** 日本語長文/改行、リサイズ、全画面、パネル非表示で文字の欠け・操作部の重なりを確認する。背景文字を中央文字へ勝手に統一しない。具体的な入力上限・UI方式は提案段階。
- **提案値:** v0.1の240字/8行、速度0.2〜2倍、大きさ50〜150%、コウモリ24体はAIの仮値で、本人決定ではない。
- **確認済み技術案:** v0.1はWindows標準PowerShell/.NETのSTART.cmdでlocalhost配信。利用にNode/Python/TD/PowerShell7は不要。対応OS/ブラウザは実測してREADMEへ記載する。
- **委任要件:** ZIP容量、頂点/三角形/テクスチャ容量、初期化・切替・描画時間、ループ/リスナー/CPU・GPU資源の収支を記録する。見た目や流体を削る最適化は再現基準と差分を保存してから行う。
- **委任要件:** 本人制作/外部素材、出典、ライセンス、帰属、変更、同梱可否を台帳に記録する。原ドクロは外部モデルで配布条件未確認のため、現状では配布ZIPへ入れない。
- **候補・未採用:** CDmirのHuman Skull（OpenGameArt、CC0）は静的構造を調査済み。原作とは別形状。頭/顎の実表示・支点・姿勢・負荷と形状差を比較してから採用を判断する。
- **納品:** 動く試作、配布候補ZIP、README、権利台帳、検証記録、収録画面/操作と未収録実機カット一覧。動画未撮影・未公開を明記する。
