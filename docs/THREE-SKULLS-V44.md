# v44: three skulls by default

The user accepted v43's large source orbit and selected3 as the initial/demo count for screen balance. Runtime default, common API schema and both count selectors now agree on3. The operator remains the normal product entry and the delivered demo starts from that exact default. Live Q/E and the1–6 selector are unchanged; Reset and A/B roundtrip retain the current count.

Source orbit remains the default. Generated source poses use a display-only subset of the existing six histories: count1:[0],2:[0,3],3:[0,2,4],4:[0,1,3,4],5:[0,1,2,4,5],6:[0,1,2,3,4,5]. Three actors therefore use evenly spaced120-degree Circle phases, rather than the first three adjacent phases. This changes which existing poses are visible; it does not generate new trajectories or alter the Noise/Feedback/clock. All six histories continue to cook, and returning actors retain their running histories. At5 the six original phases cannot form five exactly equal gaps; no substitute five-body motion is invented.

The optional rows layout and explicit provided-pose order retain their previous index order. Count changes do not select rows or reset motion. Parent/jaw matrices, model, source rates, GPU/fluid/composite/B implementation and text equations are unchanged. Source orbit may cross the central text as in the accepted v43; three bodies reduce density, not a promise of zero overlap.

Verification checks startup3 across HTML/API/runtime, all three visible trajectories, screen-center balance, text bounds, live1–6 changes with continuing source time/cooks and one renderer, real Q/E keys, Pause/Reset, surviving matrices and A/B return. The short unmodified app video begins and ends with3 running skulls and demonstrates count changes in source orbit at normal speed.

This release adopts the user's approval of the v43 orbit. Real projector/highDPR/other GPUs and long event-duration acceptance remain separate. Old versions remain available. No GitHub push or public publication.
